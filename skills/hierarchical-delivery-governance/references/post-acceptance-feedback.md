# 交付验收后反馈

用户在最终验收或后续对话中提出修改时，先判断是否仍属于当前冻结契约，不直接改写已验证的 baseline、拓扑或证据。

## 当前契约内修复

如果反馈只是指出当前冻结需求尚未满足，且不改变目标、范围、接口契约、子级结构、测试或授权，则保留原 baseline：Agent 记录真实阻断，自动执行 `retry-item`，继续实现、回归、修复和复测，再重新提交 gate 与验收。

## 契约变化或新目标

出现以下任一情况时停止当前执行并回到人工需求评审：

- 目标、范围、接口、数据契约或验收标准变化；
- 需要新增、删除或重组 Task/Capability；
- 需要新的权限、外部动作或不可逆操作；
- 反馈属于不阻断当前交付的新目标。

Agent 为变化后的完整需求重新起草一个可评审的 `development-plan.md`。用户评审并选择开发方式后，再以一次确认冻结完整需求树；不能把旧确认、旧指纹或旧验收证据沿用为新授权。

## 已完成需求

已 `COMPLETED` 的需求保持终态和证据不变。后续改动使用新的需求根；可以在说明中引用原需求，但不能原地重写原包。
